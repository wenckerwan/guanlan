# 马原知识宇宙 V2：观澜兼容性适配需求

日期：2026-10-03  
状态：待观澜后续开发实施，本文不代表接口已实现或已联调。  
适用项目：独立开发的「马原知识宇宙」，未来作为观澜子项目接入。  
马原工程目录：`D:\code_files\考研政治工程文件\马原知识宇宙`

## 1. 目标与边界

马原 V2 采用独立前端、独立后端和业务存储，包含知识地图、知识星球、概念辨析、关系实验室、主动回忆和练习。观澜负责统一账号、平台入口及共享学习数据展示，马原维持独立视觉设计。

- 复用观澜账号，不建立另一套正式注册、密码及找回密码系统。
- 马原可以独立部署和访问；从观澜进入与直接访问使用同一观澜身份。
- 观澜保持账号身份的权威来源，马原维护知识内容与详细学习记录。
- 观澜收到马原学习摘要后展示，不反向覆盖马原详细学习记录。
- 如果后续决定由观澜保存某类详细记录，应先明确唯一权威存储方和迁移规则，再调整接口，避免双向重复维护。
- 不要求观澜复制马原前端，也不要求马原采用观澜前端设计。
- 本文仅提出适配要求；未修改观澜代码、数据库或部署配置。

## 3. 账号与登录适配（P0）

### 3.1 身份契约

观澜需向马原提供可在服务端验证的稳定身份：

- 稳定、不可因昵称或邮箱修改而变化的用户 ID。
- 用户显示资料：昵称、头像等实际已有字段；缺失资料允许为空。
- 账号是否有效，以及马原内容管理所需的权限信息。
- 登录失效、账号停用和退出登录后的处理规则。

马原用户映射采用「身份提供方标识 + 观澜用户 ID」，而不是邮箱或昵称。后端根据已验证会话确定用户，不接受请求体里的任意 `userId` 作为身份依据。

### 3.2 同域接入

优先支持同域子路径接入。需要约定前端挂载路径、API 代理路径和登录返回地址，验证 Cookie 路径、SSR 登录恢复及退出行为。

当前 Cookie 获取机制可以作为适配依据，但同域部署本身不等于独立后端已经完成身份验证。马原后端仍需通过观澜可信接口验证令牌，或者使用下述登录交接机制。

### 3.3 独立域名接入

独立域名无法假定直接读取观澜 Cookie。建议观澜补充登录交接能力：

1. 马原发起登录，保存一次性状态并跳转观澜。
2. 观澜完成认证，向已登记的马原回调地址返回短时、一次性授权码。
3. 马原后端通过服务端通道兑换身份，建立自己的应用会话。
4. 返回用户原先访问的马原页面。

授权码必须绑定客户端和回调地址，并限制有效期、禁止重复兑换；返回地址使用允许列表。长期登录令牌不放入跳转 URL、前端日志或普通页面消息。

若观澜未来采用标准身份协议，可以替代上述交接机制；需形成实际协议文档。本文不宣称现有观澜已经实现 OAuth/OIDC。

### 3.4 会话生命周期

- 明确应用内退出与统一退出的区别，提供可实现的失效检查机制。
- 观澜账号停用或令牌撤销后，马原不应继续无限期使用旧身份；定义会话重验证周期与失败行为。
- 401 后停止自动提交，并保留当前用户待同步操作；重新验证身份后再继续。
- 切换账号时隔离缓存、请求队列与学习记录，不能将上一账号操作提交给下一账号。
- 马原管理员权限必须由服务端授权，不依据前端缓存中的角色字段直接放行。

## 4. 知识对象与收藏、笔记适配（P0）

现有 `StudyService::TARGET_TYPES` 不包含马原概念和关系。建议新增明确类型：

| 建议类型 | 对象 |
|---|---|
| `mayuan_concept` | 知识概念 |
| `mayuan_relation` | 理论关系 |
| `mayuan_comparison` | 概念辨析组 |
| `mayuan_experiment` | 关系实验 |

实施要求：

- 扩展后端白名单、前端类型定义、收藏/笔记列表的类型名称与跳转规则。
- 马原使用稳定对象 ID，ID 不随标题变化；与观澜旧题目等对象保持命名空间隔离。
- 明确标题、ID、URL 长度限制，保持与现有数据库字段兼容。
- 跳转地址由可信配置和对象 ID 生成，不直接执行任意外部 URL。
- 知识点下线后保留个人笔记，展示「内容已调整」并提供可用的新对象映射。
- 明确笔记的编辑、删除及同步冲突规则；现有新增/删除接口不等于已经支持编辑同步。

现有收藏接口是切换状态语义，重复调用可能取消收藏。对网络重试，应增加「设置目标状态」的幂等接口或等效机制，不直接重放切换请求。

## 5. 答题与统计适配（P0）

现有单题接口只允许 `paper`、`mock`、`mistake`、`question` 来源。马原原创题建议使用独立来源 `mayuan`，原题和原答题行为保持兼容。

- 新增马原题目来源、稳定题号及内容版本，不能把原创题伪装成真题。
- 观澜统一统计中明确马原类别，避免与真题统计混淆。
- 标准答案与判分由题目权威存储方的后端确定。
- 当前通用单题接口接收客户端提供的 `correct` 字段；马原不能据此建立可信判分，应增加专用判分接口或可信服务端结果写入通道。
- 练习提交、离线重试及摘要转发使用唯一事件 ID 去重，避免统计重复累加。
- 同一道题多次真实作答可以分别记录，网络重试同一次作答只计一次。
- 回忆自评与客观题正确率分别统计，不把自评回答写入客观题正确数。

马原详细答题记录默认由马原后端保存。若观澜需要展示逐题历史，采用受控投影或读取接口，并明确它不是另一套独立判分记录。

## 6. 学习摘要接口（P0）

现有 `/study/progress` 可以表达基础进度，但不能完整表达图谱掌握、自评、回忆和复习计划。建议新增专用的子项目学习摘要接口。

以下为建议协议，尚未实现；实际路径可按观澜路由规范调整：

| 建议接口 | 用途 |
|---|---|
| `PUT /api/v1/integrations/mayuan/summary` | 马原后端提交用户学习摘要 |
| `GET /api/v1/study/mayuan/summary` | 当前用户读取马原摘要 |

建议摘要字段：

```json
{
  "schemaVersion": 1,
  "eventId": "唯一同步事件标识",
  "revision": 12,
  "contentVersion": "知识内容版本",
  "generatedAt": "2026-10-03T08:00:00Z",
  "visitedConceptCount": 20,
  "selfAssessedMasteredCount": 8,
  "practiceAttemptCount": 15,
  "practiceCorrectCount": 10,
  "dueReviewCount": 4,
  "lastActivityAt": "2026-10-03T07:50:00Z",
  "resumeTarget": {"view": "map", "nodeId": "稳定知识点ID"}
}
```

该示例不是现有请求体。用户归属必须由认证上下文或受限服务身份的已验证用户映射决定，不接受普通用户指定别人的摘要。

协议要求：

- 写入使用绝对摘要值，不采用每次请求累加的方式。
- `revision` 由马原服务端按用户单调增加；观澜拒绝旧版本覆盖新版本。
- 相同事件重试返回一致结果；新内容版本仍可提交新的摘要。
- 自评已掌握数量不命名为客观「掌握率」；练习正确率与自评分开展示。
- UTC 时间和知识版本明确，返回统一 `{ "data": ... }` 包络及可识别错误码。
- 服务端核验非负计数、字段类型、正确数不大于作答数及对象引用。
- 管理摘要写入权限与用户读取权限分开，普通客户端不得任意修改统计。

## 7. 后台同步通道（P0）

独立后端需要观澜提供受限的服务间访问方式。后台同步不能长期依赖浏览器保留某个用户登录令牌。

- 服务身份只允许马原所需的身份验证和摘要写入能力，不授予整个观澜管理权限。
- 明确服务身份如何映射到真实观澜用户，以及凭证轮换与撤销机制。
- 用户授权范围确定后，马原事务内保存业务记录与待同步事件；观澜不可用时仍保留可重试事件。
- 后台按退避策略重试；429 遵守限流提示，401/403 暂停并处理权限问题，永久参数错误不无限重试。
- 记录事件标识、状态和错误码，日志不记录长期令牌或完整私人笔记。
- 同步响应返回确认版本，马原据此将事件标记完成。

## 8. 入口与部署适配（P0）

- 观澜增加「马原知识宇宙」入口、应用名称和描述；马原保留返回观澜的入口。
- 支持深链接到章节、知识点、辨析和练习；登录后恢复目标，刷新深链接可正常访问。
- 挂载路径和 API 地址通过环境配置提供，不写死生产域名。
- 建议优先反向代理独立马原服务，示例路径 `/mayuan/` 与 `/api/mayuan/`；这两个路径不是当前既有配置。
- 核验资源路径、路由回退、代理头、缓存和 API 路由冲突。
- 如最终使用跨域部署，配置精确允许来源及身份交接；不依赖第三方 Cookie 可用性。
- 若确需 iframe，另行验证嵌入策略、焦点与手机体验；页面消息仅处理导航等能力，不替代后端认证。
- 开发、测试与生产身份配置及数据库隔离。

## 9. 数据职责与 V1 迁移

| 数据 | 默认权威维护方 |
|---|---|
| 账号身份与权限 | 观澜 |
| 马原知识、关系、题目、来源、内容版本 | 马原 |
| 马原自评、回忆、练习明细与复习计划 | 马原 |
| 通过观澜共享接口维护的收藏与笔记 | 观澜；马原只保存缓存或待提交操作 |
| 观澜展示的马原摘要 | 马原生成、观澜保存展示投影 |

V1 数据为单个本地学习者记录，没有观澜账号字段。迁移时需要用户登录、预览导入摘要并确认归属；不能把设备旧记录自动绑定给首次登录账号。

导入需提供版本验证、去重、可追踪结果和原文件保留。自评时间与答题时间分别处理，不用最近答题时间覆盖较早但有效的自评状态。

## 10. 验收清单

- [ ] 从观澜进入和独立访问都能使用同一账号，并返回原目标页面。
- [ ] 无效令牌、失效授权码、重复兑换、错误回调地址被拒绝。
- [ ] 账号停用、统一退出和切换账号后的行为符合身份契约。
- [ ] 两个用户不能读取或修改对方的收藏、笔记、记录和摘要。
- [ ] 马原对象能够在观澜收藏/笔记页面正确展示和跳转。
- [ ] 收藏重试不会意外取消；笔记重试不会产生重复记录。
- [ ] 客户端篡改标准答案不能改变马原服务端判分结果。
- [ ] 同一次答题或摘要重复同步只计一次，旧摘要不覆盖新版本。
- [ ] 网络中断、服务器错误、限流和恢复后的重试可验证。
- [ ] 自评、浏览、回忆、练习统计有清楚且不同的含义。
- [ ] 深链接、刷新、登录返回和手机入口正常。
- [ ] V1 导入明确归属并能去重，切换账号不串数据。
- [ ] 现有真题、错题、收藏、笔记和登录流程回归通过。

## 11. 推荐实施顺序

1. 确定身份交接、用户 ID 和服务间授权契约。
2. 扩展知识对象类型及平台入口，约定深链接。
3. 实现摘要接口、服务端版本控制和事件去重。
4. 对齐题目来源、可信判分、收藏幂等和笔记编辑能力。
5. 完成部署代理、账号生命周期和 V1 迁移联调。
6. 按上述清单验收，并补充实际请求/响应示例及部署参数。

可选后续能力（P1）：在观澜首页展示待复习提示、统一搜索马原知识、跨项目学习报告。它们不应阻塞基本账号与数据接入。
