## 注册验证码现状与修复

- 邮件服务关闭时，自助注册和发码返回 503；管理员创建账号不依赖邮件。
- 开启时使用 6 位随机码、10 分钟有效，每码最多 5 次错误；同邮箱 60 秒冷却、每小时 5 次，同 IP 每小时 60 次。
- 原实现检查次数/发送配额后独立保存，存在并发穿透。修复后发送与消费共享邮箱锁，发送额外锁定 IP；固定顺序获取锁，在数据库事务内检查并预占，SMTP 在提交后执行，失败仍消耗配额。
- 消费只检查最新验证码，不能使用最新验证码后回退旧码。错误计数与 used_at 更新持有行锁。
- 新迁移创建 `email_verification_locks`（InnoDB）。先备份，再对目标版本执行标准迁移流程；未迁移不得切换新 API。锁行不可在线随意删除，否则可能破坏互斥。
- 网关认证限速仍为每 IP 5 次/分钟、burst 10；这是额外防线，不替代服务端原子限制。

## HttpOnly 会话

浏览器的 `/api/v1/` 必须转发至 Nuxt BFF，再由它访问内网 PHP API。会话由服务端写入 HttpOnly/SameSite Cookie；登录响应不得把上游 bearer 返回浏览器，SSR payload 与客户端状态不得包含令牌。

生产环境将 `NUXT_SESSION_ORIGIN` 设置为实际 HTTPS 源，例如 `https://guanlan.wencker.top`，用于写请求精确同源校验。不要依赖客户端可控的 Host/X-Forwarded-Proto 作为可信公共源。域名改变时须同步更新该配置。

旧版 JavaScript 可读令牌不自动升级。用户在发布后需要重新登录。内部 API 仍可由可信服务使用 Bearer；禁止将 PHP 服务端口或旧 `/api/ → api:9501` 通用代理直接暴露公网。

真实 IP 的信任链须按实际网络另行验证：BFF 不应直接相信任意传入 XFF；配置不正确时应用层 IP 配额可能聚合在代理 IP，但仍应保留网关真实 IP 限流。不要为了恢复用户 IP 而信任整个公网或任意 XFF。

## 错题 AI 下线

删除 AI 分析页面、入口、生成/测试/聊天与 AI 报告接口及其专用代码，清理旧 `ai_analysis_config` 浏览器存储。普通错题、人工提分手册不受影响。历史 AI 报告数据库表和数据不做破坏性删除。

清理脚本仅能在用户再次访问新版网站时删除该站点浏览器存储；无法远程撤销曾经保存或复制的第三方 API Key。有泄露疑虑的使用者应自行在服务商处撤销旧 Key。

## 安全响应头

Gateway 对成功与错误响应统一设置 CSP、X-Frame-Options、X-Content-Type-Options、Referrer-Policy、Permissions-Policy、HSTS，并隐藏 X-Powered-By / Nginx 版本。

CSP 是兼容现有 Nuxt 内联启动脚本与样式的基线：保留 `unsafe-inline`，但禁用 `unsafe-eval`、插件、外域脚本/连接、外域表单与外域嵌入。因此不能声称已完全阻断 XSS。后续可迁移每响应 nonce 后进一步收紧 script-src。

HSTS 为一年，不含 includeSubDomains/preload，避免影响其他子域；浏览器仅通过 HTTPS 接受它。外层 HTTPS 代理不能覆盖或移除这些头；不要叠加相互冲突的 CSP。

- 最终 Web Node 回归 120/120 通过，生产构建通过；包含真实 H3 BFF 请求的登录/注册令牌剥离、发码路由、退出账号绑定、跨源拒绝，以及 SSR 不序列化凭证和学习队列账号隔离测试。
- 文档链接检查 65 条、37 个文件通过；`git diff --check` 通过。旧 AI 测试指南已标记历史归档。
- 本机没有 PHP/Nginx 可执行程序，Docker daemon 不在线：PHP lint、真实 MySQL 验证码并发测试、Nginx 配置校验及完整浏览器联调尚未执行。这些仍是发布前门槛，不可用 Node 测试代替。
- 多标签页并发登录/退出时，客户端 generation 只能隔离页面状态，不能完全控制浏览器接收 Set-Cookie 的先后顺序；账号绑定可阻止已切换账号的旧写请求，但不等于已解决全部同账号会话更新竞态。进一步收敛需服务端会话版本或跨标签页认证变更互斥。
- 本轮没有升级依赖，前次审计中的依赖公告需另行评估处理，不能声称项目已无安全风险。
