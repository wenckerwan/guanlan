# 第一批实施计划

用户已同意检查后的更新规划。本批先完成账号与本地记录可靠性，保留玻璃主题、栏目和路由；在当前基于main且包含最新安全补丁的工作区实施，不回退到归档原型，不删除既有未跟踪文件，不发布生产。

设计：史纲以服务端确认的稳定userId分库，游客独立，仓库绑定不可变凭证，失效/销毁后停止网络操作；账号变化重建组件，跨标签切换通过storage/focus检查Cookie，所有请求再核对当前Cookie。旧共享库保留，主动导出后由用户确认导入，不自动归属。认证请求以token和代次隔离，成功/失败均不污染新会话；只有当前401撤销认证。马原抽取可测试本地存储适配器，捕获读取/写入故障；损坏原文受保护，保存前先隔离备份；内存导出、保存重试、页面离开刷新防抖队列。

相较于只修改默认库名，该方案也阻断旧组件继续用新凭证写入；相较于引入全站状态框架，它保持变更集中在原有入口与适配器。

任务均按失败测试→实现→回归执行：

- [x] 认证：新增auth-session测试，覆盖旧成功/401/500、当前401/网络故障、缓存不可用；修改useAuth。
- [x] 史纲：新增history-study测试，覆盖A/B/游客隔离、旧库保留、请求中途换号、离线重试、销毁；修改仓库和history入口，补主动迁移入口。
- [x] 马原：新增local-state测试，覆盖配额/安全错误、损坏/错误结构、备份保留、内存导出与防抖刷新；修改app.vue接入并展示状态。
- [x] 执行主站和马原全量前端测试、两站构建、文档/差异检查；本地浏览器验证账号切换和存储故障流程，记录真实边界。

第一批之外的AI计次、导入工具测试、CI、今日复习暂不混入本批。原有导入数量失败维持已知状态，不以本批宣称全仓库检查通过。
