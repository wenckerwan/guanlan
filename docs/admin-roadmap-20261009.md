# 管理后台后续开发规划

日期：2026-10-09。基准：main / 5dce800；玻璃主题与现有板块、导航、路由继续使用。

## 已完成基线

第一阶段已上线：部分更新保留发布状态、缺失 ID 拒绝、非法状态校验、最后管理员保护、密码重置撤销会话、危险操作确认、删除事务回滚、内容导入覆盖保护。详见 [生产发布记录](admin-reliability-production-20261009.md)。

导入保护当前采用「拒绝全量覆盖维护内容」，尚未实现源数据与后台修订的自动合并；生产完整编辑流程也尚未验收。后续不能把这两项视为已经完成。

| 2B | 内容列表完整可查 | 时政与分析分页/搜索/筛选、押题翻页、真题题目翻页；筛选条件写入 URL | 2A 的共用列表行为 |
| 2C | 错题与审计可定位 | 考生检索、错题模块/错误类型筛选、审计操作人筛选与完整详情、评论关键词/文章定位 | 2A、2B |
| 3A | 时政与分析能够完整编辑 | 管理员详情 API、标题/摘要/正文编辑、Markdown 预览、安全渲染、目录/字数生成、保存反馈 | 2B；明确已有 HTML 与新增 Markdown 的兼容方式 |

| 4 | 总览与运营统计 | 日期范围、访问次数、注册/作答/学习趋势、指标说明、详情下钻、审计时间/对象筛选 | 前面列表可查；确认每项指标的数据来源 |

每个批次独立开发、验证、交付；批次之间不要求一次性重写后台。界面改进随批次同步进行，最后一批处理整体布局和批量操作。

## 下一批：2A 用户管理

### 具体范围

- API 将现有用户数组响应改为 items/total/page/perPage；同时更新唯一后台调用方，核对其他调用方后切换。
- 默认每页 20 条，上限 100 条；支持邮箱/昵称关键词、角色、状态、用户组；按 ID 倒序稳定排序。
- 页面显示筛选后的真实总数与当前页；切换筛选重置为第 1 页，刷新/返回保留 URL 查询条件。
- 区分加载中、确实为空、请求失败；失败可重试，旧数据若暂时保留需明确标识，不能把失败显示成零用户。
- 保留已上线的创建、角色/用户组调整、启停、编号绑定和密码重置；操作成功后按当前筛选重新读取，正确处理记录离开筛选结果和末页为空。
- 保存期间禁用对应操作；无权限或会话失效显示清晰提示，避免依赖过期本地角色缓存。
- 提炼必要的列表状态与分页组件；其他业务页仍按自己的字段与操作组织。

### 验收

- 以独立测试库构造超过 50 位用户，全部能通过翻页或搜索访问；总数、页数和组合筛选准确。
- 非法筛选及页大小有一致校验或规范化规则，明确空白关键词处理；不因联表重复计算用户。
- 服务返回 401/403/500 时，页面提示与重试正确；快速切换筛选不被旧请求覆盖。
- 创建、禁用、用户组变更之后，列表仍符合筛选条件；分页边界正确。
- 管理员防误操作、最后管理员保护、密码会话撤销回归继续通过。
- 浏览器验证「搜索—翻页—修改—刷新」；生产核验以读取和权限拒绝为主，真实写入使用明确的测试记录。

### 完成后再开始

2B 时政/分析列表改造，复用 2A 的分页与状态组件；之后推进 3A 正文编辑。若用户更需要内容编辑，可在 2B 后优先开展 3A，将错题/审计增强安排在其后。

## 内容来源规则

- 现有 Markdown/JSON 资料保留为可编辑来源；后台修订不能默默被下一次导入覆盖。
- 全量导入保护保持开启；解除保护需要备份、差异审查和明确的合并决定。
- 修订冲突优先显式报告；不以「最后保存覆盖」处理多人编辑。
- 已有 HTML 不自动当成 Markdown；转换与渲染策略在 3A 中明确。
- 草稿状态需完整覆盖数据库、校验与前台可见性；在该设计完成前仍只使用 published/hidden。

## 统计规则

- 访问次数与用户人数分别展示，沿用已有访问去重规则。
- 新增注册、活跃、学习时长、作答和正确率各自定义口径；数据不足的指标不估算为事实。
- 展示北京时间、统计区间、更新时间；请求失败不展示伪造零趋势。

## 每批发布流程

从最新 main 建开发分支 → 记录本批范围 → 行为回归与真实 MySQL 检查 → 前端测试/构建/浏览器流程 → 针对改动审核 → 交付记录 → 按用户授权合并与部署 → 备份/迁移/公开验证/回退保留。

本文件是后续路线与验收建议；没有实施新功能，也没有把未来各批次的生产部署视为已授权。
