## 验证结果

- 主站、马原、New API 以及原 API、数据库、Redis 服务保持运行，所检查业务容器均 healthy。主站公网 HTTPS、主站/马原内部页面及 New API status 返回 200。
- 主站和马原复用原线上完整应用产物，仅替换运行环境；实际 Node 命令输出均为 24.22.1。题库、排行榜、马原 content 的匿名请求仍返回 401。生产排行榜的角色/分组展示未被本次组件发布移除。
- New API 先在断网容器和数据库副本上完成迁移检查，再更新生产。原有 22 项配置值不变，仅新增一项默认项；上线后用户 2、渠道 2、令牌 5 的记录数不变，SQLite integrity_check 为 ok。
- SillyTavern 页面、`/version`、`/lib.js` 实际请求通过；Basic Auth 仍要求认证（匿名 401）。**923 个聊天与角色文件逐一 SHA256 比对完全一致**。
- SillyTavern 在本机使用官方 `docker/build-lib.js`、正式 tag `7e8663c` 和原锁文件构建。前端库 SHA256：`2d5fb1eedcbefe7062421e8ca54b90a23312f64df8d480c16538714c5157e0bf`；Webpack cache key：`9d66c67b69336e0c`。
- 为避免 4GB 宿主首次编译占用约 800MB，增加 `src/prebuilt-webpack.mjs` 和一处 middleware 适配。只复用上游版本/commit/webpack 计算键相符且 SHA256 全部验证通过的产物；不改变业务接口或认证。该适配 5 项先失败后通过的测试及独立源码审查完成。候选受 512MB cgroup 限制时约 173MB，最终生产约 218MB；生产日志确认使用预编译库。
- 主站 80 项、马原 34 项本地测试通过；仓库 `git diff --check` 通过。
- OpenResty `nginx -t` 通过并已 reload；最终展开配置中活动 QUIC 监听为 0。**这不是 OpenResty 代码补丁，仍需等待厂商发布修复镜像。**

未使用旧发布文档中的 `api.wencker.top` 作当前 New API 公网验证入口：该域名已不在现有站点配置中，会落入 1Panel 默认站点。New API 检查针对实际端口 `127.0.0.1:3001`。未执行付费模型调用或真实聊天生成，以免产生费用。

## 部署位置与回滚

- 服务器备份：`/www/backup/component-upgrade-20261022-01`，目录权限 700。包括原镜像固定标签、部署配置、New API SQLite 一致性备份、SillyTavern 约 546MB 数据备份、Git bundle、原配置和 Node 链接目标。
- 发布目录：`/www/releases/component-upgrade-20261022-01`。正式 SillyTavern 源码在 `/opt/SillyTavern`；原版本保留于 `/opt/SillyTavern-before-components-20261022`，两版的数据路径都指向 `/opt/SillyTavern-user-data`。切换版本不会用旧备份覆盖新产生的聊天。
- 回滚入口：备份目录下的 `rollback-web.sh`、`rollback-newapi.sh`、`rollback-silly.sh`、`rollback-edge-mitigation.sh`。New API 常规回滚只换镜像，不自动恢复旧数据库。
- 服务器 Compose 与源码 Dockerfile 已固定运行版本；本地项目的生产/开发镜像与 README 同步更新。生产密钥文件、New API Compose、SillyTavern 配置收紧为 600。变更未自动提交或推送 Git。

过程中，候选依赖安装/编译曾造成磁盘与内存压力，已停止相应候选进程并转为串行准备和本机构建。SillyTavern 首次切换因新目录预置 data 目录导致链接未接到原数据，完整性检查触发自动回滚；修正映射后重新上线，最终原聊天与角色文件全部一致。未覆盖、清库或回滚业务数据。
