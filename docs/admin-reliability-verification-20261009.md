# 后台可靠性第一阶段交付记录

## 改动

- 时政/分析：部分更新保留原发布状态，更新不存在 ID 返回 404，非法发布状态返回 422；预测也使用严格状态校验。
- 账号：服务端事务锁保护最后一个有效管理员；重置密码原子更新密码并撤销目标账号令牌；其他账号令牌保留。
- 内容：新增 content_maintenance 表。后台维护操作与导入共享事务行锁，维护过的表禁止被 ArticleSeeder/PaperQuestionSeeder 全量覆盖；导入失败回滚，试卷强制删除失败回滚题目。
- 页面：时政/分析删除确认和失败提示；账号角色/状态确认、执行中禁用重复操作、密码遮罩；自己的权限改变后更新界面并跳转，自己重置密码后退出登录。

## 复验

Docker 镜像需包含当前项目 Hyperf 依赖与 PHP/Swoole（默认已有 `guanlan-api`）。在 Linux/WSL 执行 `bash tools/tests/run-admin-reliability.sh`，脚本创建无公开端口、使用 tmpfs 的独立 MySQL 测试库，并在退出时清理本次容器与网络；测试不连接生产。

浏览器：先在 apps/web 完成 npm run build 并以 NITRO_HOST=127.0.0.1、NITRO_PORT=3209 运行 `.output/server/index.mjs`；设置 PLAYWRIGHT_MODULE 为本机 Playwright 模块路径，执行 `node tools/tests/admin-reliability-browser.cjs`。默认使用已安装的 Edge。

## 上线与兼容边界

本次保留于开发分支，尚未推送、合并 main 或部署服务器。上线前需备份数据库，先执行新增迁移 `2026_10_09_000001_create_content_maintenance.php`，再切换 API；缺少迁移时受保护写入会拒绝执行。

迁移初始标记为未维护，无法识别上线前已经发生的手工修改；上线前必须对账生产内容与源数据，将有维护差异的相关表设置 maintained=1。这个检查不是自动已完成的生产验收。

此阶段通过拒绝全量覆盖保住内容，不自动把数据库修改写回 Markdown/JSON。需要重导入时先备份、对账并决定最终数据来源，由维护人员在维护窗口解除相关表标记后执行导入；没有网页解除或重导入按钮。

新表无需删除原有内容。若回滚旧 API，维护标记仍可保留，但旧代码不识别导入保护，因此回滚后继续禁止未经对账的全量导入；不要把删除保护表当作普通修复方法。

标题/正文完整校验、目录和字数生成、修订历史、Markdown 编辑、完整分页筛选与运营统计仍属后续阶段；本次不宣称这些已实现。真实生产管理员读写、生产迁移与发布验证未执行。
