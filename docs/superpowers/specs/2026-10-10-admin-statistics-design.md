# 后台统计与审计设计约定

在正文编辑、修订对账完成后执行，保留当前后台路由和玻璃主题。

- 总览默认近14日，可选日期范围（含首尾、最多366天）；API 明确 timezone=Asia/Shanghai 与 updatedAt。注册/作答 created_at 当前生产由UTC PHP写入，转换北京时间分组，边界用北京时间午夜转换UTC。
- 访问次数使用 site_visit_days，既有日期已是北京时间；不将访问次数称人数。
- 学习时长只有原 user_study_stats.date（当前UTC自然日）和seconds，不存在逐次跨日时间数据。保留原记录日聚合并明确 studyDateTimezone=UTC，不能伪称已精确转换为北京时间。以后若需要精准跨日时长需独立扩充数据采集。
- 趋势、区间总数、时长与活跃学习账号数来自真实对应表；不计算无依据的留存或人数。日期不合法、反向或过长返回422。
- 审计可按操作前缀、管理员ID、对象类型/ID、起止日期查询。日期边界同上述UTC记录→北京时间转换；稳定倒序、分页规范化；详情完整JSON显示、内容按文字渲染。
- UI：日期查询、加载/失败/空状态、重试、时区/口径提示、详细审计展开；数据卡片可链接对应管理页。键盘与移动端跟随每批完善。
- 批量操作只提供已明确事务与反馈语义的低风险状态修改，不增加批量硬删除。若前面正文版本约定尚未支持批量版本校验，批量操作不作为本次未定义扩展偷偷加入。
