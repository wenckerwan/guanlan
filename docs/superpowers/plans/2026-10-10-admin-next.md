# 后台后续顺序实施计划

用户批准路线：发布用户管理与审查修复 → 内容列表 → 正文编辑 → 修订对账 → 统计与体验。基于 main 和玻璃主题，不更改既有路由。

## 2B 列表

服务新增共享分页函数，稳定排序并规范化末页；hotspots/analysis 支持 q/status 及期次/分类筛选，响应 items/total/page/perPage，附完整筛选选项。mocks 与 paperQuestions 规范化末页。

前端提炼 useAdminList；从 URL 恢复并提交 q/status/period/category/page/perPage，隔离旧请求、失败重试；时政与分析页面保留所有创建/删除/上下线/评论设置操作。模拟卷增加分页，试卷展开题目增加独立分页。

行为测试：超过 100 条文章、字面搜索、组合筛选、空页回退、超过 20 模拟卷与 100 题目；浏览器 URL、错误、操作后刷新与切换展开卷不污染题目。

## 3A 正文

新增 AdminArticleService、管理员文章详情与编辑/预览接口；已有 html 保持原文，新增或明确切换 Markdown 的内容由服务端安全渲染并生成目录/字数。预览与保存共用渲染。表单提供保存反馈、错误提示、未保存离开确认；阅读区保持实体背景。

## 3B 修订对账

新增内容修订表与正文元数据（来源、Markdown、revision）。保存时提交 expectedRevision；不匹配 409，保留输入，不静默覆盖。事务中保存修订、正文和维护标记；历史只读，可选择一个旧版本作为新修订恢复。只读对账按稳定 slug 展示数据集/数据库差异与来源，不解除保护，不执行全量导入。

## 统计与体验

后台总览支持北京时间日期范围、访问次数/注册/作答/学习时长及口径说明、更新时间与错误重试；审计提供时间、操作人和对象筛选及完整详情。页面同步键盘/移动端和操作中状态；批量操作按可回退、单条失败可追踪原则限定范围。

每阶段先写失败测试，再实现；真实 MySQL + 浏览器 + PHP/文档/前端测试 + 构建验证，逐批提交并更新 progress。初次发布已授权；后续发布依完成验证和本次顺序开发授权推进，避免只留下不可审查的半成品。
