# 后台可靠性实施计划

目标：落实后台盘点第 1 阶段，基于 main 玻璃主题，保留页面、导航与路由。

- [x] 回归测试：调用真实 AdminService，覆盖隐藏记录部分更新、无效 ID、非法状态、最后管理员、密码会话撤销和试卷删除事务。
- [x] 保存规则：部分更新保留已有状态；非法状态拒绝；缺失 ID 返回 404；新增和更新控制器处理 422；预测复用严格状态校验。
- [x] 账号保护：事务内按 ID 顺序锁定有效管理员和目标用户，保护最后有效管理员；密码修改与令牌删除同事务。
- [x] 内容导入保护：后台内容写操作记持久维护标记；导入脚本在任何清空前检查标记，发现维护记录拒绝全量覆盖并给出对账说明，不开放网页导入按钮。
- [x] 前端保护：热点/分析删除确认、失败提示和执行中锁定；账号角色/状态确认、密码遮罩、执行中锁定；自己账号更新后刷新权限。
- [x] 验证：本地 PHP 容器执行行为回归和语法检查、前端既有测试与构建、git diff --check。真实 MySQL 并发与迁移验证如本地容器可用则执行。

导入兼容方案：本阶段选择阻止已被后台维护的表被全量重建，保留现有离线数据源结构；合并导入、修订回写和冲突解决属于后续内容维护阶段。标记为表级，覆盖删除及纯状态操作；检查必须先于 ArticleSeeder/PaperQuestionSeeder 的任何写入。上线前先备份，迁移为新增维护标记表。历史已发生的后台修改不能凭空恢复，首次上线前仍需核对现有数据库与源数据。

范围：开发与本地验证；本次未授权生产部署，不在生产运行写入或迁移。
