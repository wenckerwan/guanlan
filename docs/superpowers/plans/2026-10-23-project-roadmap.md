## 三、版本路线与验收

### 阶段 0：dev.29 交付收尾（P0，新增功能前）

**交付：** 可复核的稳定性版本和当前状态清单。

- [ ] 读取对应提交的 CI 结果；缺失时在独立环境执行 PHP/MySQL、真实 Docker 发布成功及失败演练。
- [ ] 验证 AI 完整流、断流、401、回退、历史读取和恶意 Markdown；真实供应商链路在具备调用授权与测试配置后执行。
- [ ] 验证史纲离线编辑、删除、重连、存储失败和 A→B→A 切换。
- [ ] 重新核对最新生产 SHA、镜像和迁移状态；服务器维护解除且具备发布授权后安排部署与上线验收。
- [ ] 为历史总规划建立当前路线图入口，将旧阶段标为历史安排，保留事实记录。

**验收：** 每项有环境、提交、执行结果；发布失败能恢复上一应用镜像；不为应用回退覆盖业务数据库。

### 阶段 1：dev.30 账号云同步（P1，已有方向，本次细化建议）

**交付：** 优先打通马原本地学习状态与主站账号，复用史纲的成熟离线处理经验。

- [ ] 盘点马原本地字段和 v2 后端能力，形成“字段—账号归属—服务端接口—迁移规则”清单。
- [ ] 首批同步收藏、笔记、概念自评、回忆和练习记录；阅读位置按实际价值单独决定，不直接上传全部浏览轨迹。
- [ ] 首次登录展示本地数据数量，用户主动选择迁移；迁移前可导出，不自动归入共享设备上的当前账号。
- [ ] 每条待同步变更有稳定标识；重试不重复生成练习记录，删除用明确的删除记录传递。
- [ ] 离线变更持久化后才显示已保存在本机；服务端确认后才显示已同步。
- [ ] 笔记并发修改保留双方版本并提示选择，禁止静默覆盖；集合操作和练习事件分别定义合并规则。
- [ ] 账号切换立即隔离缓存与队列；旧账号请求返回不能写入新账号页面或本地空间。

**验收：** 两设备同账号互通；断网重连不丢数据；重复提交不重复记账；A/B 数据不串号；删除不被旧设备复活；退出后私有数据不向下一位使用者展示。同步对象限制、批量大小和保留期需在实施方案中量化。

### 阶段 2：dev.31 AI 调用与额度（P1，建议版本）

**交付：** 配置规则、调用次数和界面提示一致。

源码检查仍能看到分析接口必填 apiKey，而自定义供应商说明允许可选 key；额度仍在报告保存路径出现。这是本轮需复现确认的具体切入点。

- [ ] 统一连接测试、对话测试、分析和前端表单的供应商校验。
- [ ] 明确用户组额度是“分析调用次数”还是“保存次数”；建议使用每日业务分析次数，实施前确认失败扣额、抽取计数和管理员规则。
- [ ] 采用独立持久额度记录与请求幂等标识；删除报告不恢复调用额度，流式回退关联原操作。
- [ ] 返回可理解的额度、失败与重试提示，错误和日志不泄露密钥及私人输入。

**验收：** 并发争抢最后一次额度最多一个成功；重试与回退不重复扣额或导入；跨日按明确业务时区计算；非法配置在调用前拒绝。

### 阶段 3：dev.32 学习任务与复习闭环（P1，建议版本）

**交付：** 个人首页回答“今天学什么、哪里薄弱、哪些错题到期”。

- [ ] 将已有错题排期接入每日任务，不另造一套复习状态。
- [ ] 支持考试目标日期、每日可用时间、任务完成与延期；学习日采用明确时区。
- [ ] 汇总主站、马原和史纲的学习事件，区分真实真题、原创题、自评与阅读记录。
- [ ] 展示分模块正确率、首次与重练表现、到期任务、近期变化；说明统计样本和时间范围。
- [ ] 用户可导出个人记录；题目失效和内容改版不删除历史作答。

**验收：** 任务可完成、延期、重算；不重复计入同一事件；没有记录时显示空状态；指标能追溯到具体学习行为。

### 阶段 4：dev.33 题库、检索与知识关联（P2，建议版本）

**交付：** 从考点进入相关真题，从错题回到知识解释。

- [ ] 统一考点标识与映射，优先覆盖已有马原概念和史纲事件，再逐步整理其余学科。
- [ ] 补充题型、年份、科目、考点筛选、关键词高亮与无结果提示；先测现有检索耗时，再决定索引方案。
- [ ] 支持按科目、考点、题型和题量组卷，保存题目版本及作答记录；题量不足明确提示。
- [ ] 建立用户纠错—管理员审核—修订发布—关联题更新的流程。

**验收：** 已有关联可双向跳转；无来源关系不虚构；出卷约束准确且不重复抽题；正确率不会混淆不同题库和版本。

### 阶段 5：dev.34 内容运营与后台补齐（P2，建议版本）

**交付：** 内容更新和纠错有来源、有审核、有版本。

- [ ] 以最新后台源码和已验收报告核对缺口，避免重做已有分页、正文编辑、修订和审计功能。
- [ ] 将时政整理、来源、审核、考点标签、发布与撤回形成固定操作清单；初期继续人工审核。
- [ ] 做好源资料变更与后台修订差异展示，人工确认合并，全量覆盖保护继续保留。
- [ ] 补齐确有需要的题目/预测/模拟卷维护与移动端操作；运营指标标明统计口径。

**验收：** 未发布内容不会出现在前台、搜索或关联接口；旧版本保存触发冲突；发布、撤回和合并均可审计。

### 阶段 6：dev.35 资料阅读与移动体验（P2，建议版本）

**交付：** 有效资料可安全阅读，手机能完成核心学习路径。

- [ ] 清点有权展示的 PDF/讲义，记录来源、摘要、版本与文件哈希，建立幂等导入。
- [ ] 实现 PDF 页码定位、目录、阅读进度和笔记关联；大文件按需加载。
- [ ] 明确预览、全文和下载权限；原文件不能靠可猜 URL 绕过鉴权。
- [ ] 优先修复手机导航、触控、长文、练习和图谱降级；在容量和隐私方案通过后再增加 PWA 离线包。

**验收：** 手机可完成登录—阅读—练习—复习；低性能设备有可用回退；离线缓存可清理且账号退出后不泄露私有资料。

### 阶段 7：V0.2 稳定发布（发布里程碑）

**交付：** 核心学习流程可持续运行和维护。

- [ ] 完成关键账号、同步、练习、AI、内容权限和后台维护的真实集成验收。
- [ ] 在独立环境恢复备份并核对学习记录与内容摘要，记录实际恢复耗时；据此确定备份频率与恢复目标。
- [ ] 建立 API 错误、延迟、磁盘、备份失败及同步失败的监控；告警只在明确责任人和渠道后启用。
- [ ] 根据 2 核 / 4 GB 历史服务器基线重新测量实际容量，缓存和搜索服务按瓶颈引入。
- [ ] 发布说明包含运行版本、迁移步骤、验收结果、已知限制和回退入口。

**验收：** 核心流程无未关闭的发布阻断问题，备份可恢复，应用可回退，关键故障可发现，维护步骤可复现。若某可选模块延期，应从稳定版承诺中明确移除。
