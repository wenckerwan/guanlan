## 发现

### P1：密码重置存在并发登录令牌签发窗口

定位：AdminService.php:214–226，AuthService.php:60–68，AuthController.php:100，Support/Auth.php:20–31。

登录先查询密码并完成 password_verify，之后在控制器单独调用 Auth::issue。管理员重置密码在另一事务中改密码并删除令牌。因此「旧密码已验证 → 重置并删令牌 → 原登录请求签发新令牌」可以成立；新令牌签发不复核凭据版本，后续 resolve 只检查有效期和账号 active，导致重置后仍可留下由旧密码认证取得的有效会话。

隔离复现调用真实 AuthService、AdminService、Auth::issue，替换数据库边界并按上述顺序执行，确认重置后令牌数先为零、随后重新产生一条。不是生产请求，也不是完整 MySQL 并发测试。

建议：将密码验证和令牌签发纳入同一个账号锁/事务边界，或引入凭据版本并在签发与解析时校验；增加并发登录/重置用例。现有“重置删除已有令牌”测试不能覆盖这个窗口。

### P1：启用邮箱验证码时后台不能创建用户

定位：AdminService.php:199–201，AuthService.php:20–33，AdminController.php 的 createUser。

管理员创建调用公共 register(email,password,displayName)，没有提供 code。注册在 Mailer::enabled() 为 true 时要求验证码，但后台页面/API 均无验证码参数，结果始终返回“请先获取并填写邮箱验证码”（控制器将该错误返回 409）。

隔离复现使用真实服务，Mailer 边界设为启用，确认 createUser 返回上述错误。未核验当前生产邮箱开关，结论适用于启用验证码的配置。

建议：提供经过管理员权限校验的账号创建路径，复用账号/错题本原子创建，明确管理员代建是否需要验证；不要通过全局关闭邮箱验证绕过。增加真实创建流程测试，目前浏览器创建测试使用模拟 API。

### P2：评论模式修改没有接入导入保护

定位：CommentService.php:39–52，ContentMaintenance.php:24–32，ArticleSeeder。

setMode 直接更新 comment_mode 并 save，没有调用 ContentMaintenance::write，也不共享导入锁。在维护标记为 false 的表上，只调整评论为 closed/review 不会标记已维护，后续全量导入仍被允许，重建文章会丢失评论模式设置；并发时也无法依靠该共享锁保护。

此项由真实代码路径核对得出，没有执行破坏性导入。已有生产发布记录中的五表 maintained=1 是当前发布的保守保护，但不消除新安装或解除保护后的代码缺口。

建议：按文章类型映射表，在同一 ContentMaintenance::write 事务内保存模式，并测试修改模式后重导入拒绝及并发情况。

### P3：文档检查存在 6 处失效链接

tools/doclink.py 返回失败，均来自 docs/AI-ANALYSIS-TEST.md：5 个相对代码链接的目录/行号写法不被检查器正确定位，另一个 /d/.../SKILL.md 是本机绝对路径。应改为从 docs 出发的有效相对路径，并去掉公开文档中的本机依赖链接或提供可用仓库来源。
